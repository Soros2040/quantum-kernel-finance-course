# 天衍能力验证范围

状态：离线前置验证。本页规定一组待提交的功能与规模抽查，不报告这些线路已经在云端运行。生成脚本没有认证、网络或提交功能。实际提交的必要条件为“免费且不消耗真机额度”；目前缺少后半项的明确证据，因此云端提交保持停止。

## 1. 检验对象和结论边界

目标后端固定为天衍全振幅仿真器 `tianyan_sw`，接口依据为官方 Cqlib 1.3.11。它属于云端经典仿真，不是量子硬件。此前留存的独立容量探测已观察到全振幅30比特线路返回读数；这些探测没有验证本课程的核矩阵、候选选择、金融预测或吞吐量。本页只准备下述12个新任务，不能用旧容量结果替代新线路核验。

4比特线路采用本课程四候选：Q1、Q2分别为尺度0.5、1.0的一层RY编码；Q3、Q4在两次相同尺度编码之间加入有向相邻CNOT链。核重叠线路先执行U(x)，再按门序逆序执行U(y)的逆；RY角取负，CNOT自逆，但整条链的门序仍须反转。末端测量全部比特，以全零事件估计保真度。逻辑比特0至q−1显式映射到QCIS标签Q1至Qq。

8和12比特只将合成四维参数重复扩展，并使用尺度0.5、两层编码和跨全部比特的相邻CNOT链。这是小幅规模抽查，不把它们当作金融特征扩展或课程新增候选。

## 3. 已核接口能力与待核项

官方1.3.11提供`Circuit.ry`、`Circuit.cx`、`measure`／`measure_all`、参数赋值与QCIS加载。`Circuit(4)`默认创建Q0至Q3，因此不能直接套用到本清单的Q1至Q4标签；应使用显式标签列表或核对QCIS解析得到的标签。标准库生成脚本直接输出已冻结的QCIS文本。

该SDK将CNOT命名为CX；其QCIS兼容导出还可以使用目标位H—CZ—H分解。实际使用直接CX还是分解必须记录。清单中的门数、深度是显式逻辑指令的资源调度结果，尚不包含服务端编译、映射或消去；服务端未返回编译线路时，不给出编译后规模。

官方后端资料中全振幅列有RY、CX、H、CZ、M。稳定子门集不支持本课程的一般连续角RY；单振幅输出语义不同，不能自动替代逐次测量；张量网络与带噪声后端均不在本清单的授权目标中。带噪声模拟也不能省略噪声模型的冻结。

离线数值验证须独立检查：同点核为1；两种一层核满足∏j cos²[aπ(xj−yj)/2]；Q3、Q4的交换输入核值相同；显式重叠线路的全零概率与两份状态内积一致。该验证不读取精确值来改变线路或挑选云端结果。状态向量计算与云端返回分别留痕，不能混写为实测。

2026年11月9日已完成这12条线路的本地验证：独立解释QCIS逐门作用，并与课程量子核心的状态内积比较，全零概率最大绝对差为1.12×10^-15；同时核对了门数、逻辑深度、末端标签、解析样例和交换输入。随后在独立环境以现有Cqlib1.3.11实际调用`Circuit.load`解析12条线路，全部通过；解析比特数、测量标签、指令数及含测量深度与清单相符。默认构造的Q0起始编号和显式Q1起始编号分别核对。普通导出保留门序和数值参数；QCIS兼容导出与将CX展开为目标位H—CZ—H的规则一致，重新解析也通过。此处均为实际离线验证结果，没有创建平台对象、认证、安装SDK或提交云任务，不能写成服务端验收通过。

兼容导出会改变显式指令资源：4比特两层重叠从26条总指令／含测量深度11变为38条／19；8比特为54条／19变为82条／35；12比特为82条／27变为126条／51。它们仍不是服务端编译后规模。原冻结QCIS保持直接CX版本，未因离线导出而替换或提交。

## 4. 提交之前的精确前置条件

提交前必须同时具备：

1. 确认选定目标是`tianyan_sw`仿真器，当前`isToll=1`且`status=0`，账户范围和接口符合本清单。
2. 取得适用于该账户、后端和提交接口的官方计费条款、套餐说明，或无需执行的费用预估，明确这些调用对真机机时／额度的扣减为0。仅有免费标志、后端可见、余额快照或没有收费报错均不满足此项。
3. 核对单任务512shots、12次／6144shots总上限、线路哈希、规则验证、全局串行、查询截止与禁止自动重提的约定。
4. 在独立运行环境确认Cqlib1.3.11的实际导入和离线解析；不得隐式升级SDK、换后端或读取公开文件中的凭据。

当前缺证明确为第2项。已读官方SDK及MCP工具材料尚未核实账户额度查询入口，也没有找到仿真与真机额度独立的明确说明。这是所核材料的边界，不是断言平台没有该功能。不能先提交一条再观察余额来试探；结算可能异步，且试探本身已经可能消耗用户明确要求保留的额度。

## 5. 获准执行后的记录要求

既有执行器可复用单次提交、提交前落账、任务ID、全局串行锁、输入哈希、原始响应与未知状态阻断。但其旧预算、每次100shots和16编码层约束属于旧容量探测，须显式适配，不能通过换目录绕过未决任务。失败或无结果的提交尝试也保留在本轮请求预算中，重试需要独立决定；结果不可用不自动退还尝试额度。

已获得任务ID的超时只续查同一ID；未获得ID的提交超时保留为提交状态未知，不自动重提。客户端停止等待不等于服务端终止。只有原始响应明确给出失败或拒绝时，才能改变相应状态；若失败原因未返回，原因记未知，不能写成内存不足或达到容量上限。旧任务的后来查询结果以追加状态记录保存，不覆盖旧观察快照。

成功返回后逐项核对任务ID、测量标签、512行二进制读数、行宽、末端全测量、概率表与原始直方图关系、返回线路哈希。`resultStatus`首行为标签，不能算作一次shot。概率字符串的位序须用标记态实证核对，不硬编码沿用旧任务。新版SDK可能由`round(probability×shots)`合成counts；缺少原始读数时只报告概率输出，不能作为有限测量方差的实证。

512shots不足以认证服务端采样独立性或数值精度。Bell频率、非平凡核值与精确参照用事先冻结的二项抽样区间作描述性核对；交换输入的两条线路使用独立采样时不要求计数相同。正式给出通过／不通过阈值前应记录多项比较口径。所有耗时区分提交时间、首次观察结果时间与服务端计算时间；后者未返回则记未知。
